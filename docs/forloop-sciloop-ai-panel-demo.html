What We Created

We created a dedicated SciLoop AI panel inside the ForLoop Control Panel. This panel works like an operator dashboard for the AI layer of SciLoop.

  • It checks whether the SciLoop AI backend is running.
  • It checks whether AI provider keys are available and usable.
  • It can trigger the SciLoop AI backend start flow from a safe control endpoint.
  • It connects the News Portal, AI explanation system, and Visual Language Lab.
  • It keeps secret API keys away from the browser UI.

Architecture

How the SciLoop AI Panel Connects Everything

The panel is not just a button. It is a bridge between the user-facing platform and the protected backend AI services.

1. SciLoop UI User clicks Explain, Simulate, or Visualize inside the News Portal.
2. Next Proxy Browser calls safe app proxy routes instead of exposing private backend URLs.
3. SciLoop AI Backend Backend creates prompts, applies fallback logic, cache, and quota protection.
4. AI Provider Router Gemini, Groq, OpenRouter, Hugging Face, Together, and other providers can be selected.
5. SciLoop Output Explanation, simulation, timeline, and visual plan are returned to the frontend.

ForLoop Control Panel Role

  • Shows SciLoop AI status and readiness.
  • Saves/checks provider keys locally.
  • Starts the SciLoop AI backend through an allowlisted runtime target.
  • Logs important admin actions for demo visibility.

SciLoop AI Backend Role

  • Receives article or concept data from SciLoop.
  • Builds safe prompts for explanation, simulation, and visual planning.
  • Calls the selected AI provider server-side.
  • Returns clean JSON that the UI can render beautifully.
Important: The AI key is never placed inside the HTML page. The browser sends a request to the backend, and only the backend talks to Gemini/Groq/OpenRouter-style providers.

APIs Used

Main Backend APIs Behind the Panel

Area Endpoint Why It Exists
ForLoop SciLoop AI Panel GET /api/admin/sciloop-ai/status Checks whether the SciLoop AI backend and provider configuration are visible to the control panel.
ForLoop SciLoop AI Panel GET /api/admin/sciloop-ai/readiness Shows if enough required provider keys are configured before a live demo.
ForLoop SciLoop AI Panel POST /api/admin/sciloop-ai/keys Saves provider keys into the local backend environment, not into the frontend.
ForLoop SciLoop AI Panel POST /api/admin/sciloop-ai/check-provider Tests one provider key and returns ready, missing key, quota, or warning state.
ForLoop SciLoop AI Panel POST /api/admin/sciloop-ai/check-all Runs a full provider readiness check for the control dashboard.
ForLoop SciLoop AI Panel POST /api/admin/sciloop-ai/start-server Starts the allowlisted SciLoop AI backend runtime target.
SciLoop AI Backend POST /api/sciloop-ai/explain Turns news into simple meaning, timeline, people/team info, impact, and visual blueprint.
SciLoop AI Backend POST /api/sciloop-ai/simulate Creates a possibility simulation storyline from the AI explanation.
SciLoop AI Backend POST /api/sciloop-ai/news-visualize Converts a news article into a visual-plan handoff for the Visual Language Lab.
SciLoop AI Backend GET /api/sciloop-ai/news-visualize/:handoffId Lets the Visual Language Lab load the prepared visual plan after redirect.

Frontend Proxy Routes

  • /api/sciloop-ai-proxy/* forwards SciLoop AI requests safely.
  • /api/forloop-proxy/* forwards ForLoop admin requests safely.

Provider APIs Used

  • Gemini for structured explanation and planning.
  • Groq for fast response generation.
  • OpenRouter/Hugging Face/Together as optional provider routes.
  • Local fallback when providers fail or keys are missing.

Demo Flow

What Happens When a User Clicks “Explain with SciLoop AI”

1 User action User opens News Portal and clicks Explain with SciLoop AI.
2 Payload Frontend sends title, summary, source, URL, and date.
3 Backend prompt SciLoop AI Backend builds a structured prompt for simple explanation.
4 Provider call Provider router uses available APIs and switches if one fails.

  • Simple meaning of the news.
  • Why the innovation matters.
  • Team or people behind it when confirmed.

  • Prompt construction.
  • Provider selection.
  • Quota/cache protection.
  • Error handling.
  • Fallback explanation if AI provider fails.
  • Safe JSON response for the UI.

Security + Reliability

Why This Architecture Is Safe for Demo and Expansion

01

Keys stay hidden

AI provider keys are read from backend environment files. The browser never receives real API keys.

02

Panel is controlled

ForLoop admin actions use a local access code and allowlisted runtime actions instead of open shell access.

03

Failures do not break UI

If a provider fails, hits quota, or times out, SciLoop can switch provider or return local fallback content.

04

Quota protection

The backend uses cache, cooldowns, limits, and provider status checks so demos do not burn API usage unnecessarily.

05

Clean JSON contract

The frontend receives predictable fields, so the explanation card, timeline, and visual lab can render reliably.

06

Expandable

The same pattern can support more providers, more subjects, voice, visual plans, and future learning tools.
